# 野外丰容 P0 R1：空间骨架、草地分层与工作场景

## 1. 目标

把当前围栏外“连续地面 + 围栏草环”的空旷感，变成有尺度、有方向、有使用痕迹的乡野环境；**菜园仍是视觉和交互中心**，不扩成自由行走地图，也不靠堆实例或大贴图制造密度。

P0 解决四个问题：

1. 远近草地缺乏层次；
2. 围栏外缺少明确的空间方向和进入/离开关系；
3. 缺少可识别尺度参照；
4. 远景地面连续但视觉用途单一。

## 2. 必做内容

### P0-A — 草地三层化

- **地表层：** 由现有 terrain / hardscape 材质承担远距离的大面积绿色、干草带、踩踏区、车辙和裸土变化；不把远景全靠真实草叶填满。
- **中远草层：** 增加专用低面数草簇，覆盖围栏外较大范围，形成田野轮廓和风浪。
- **近草层：** 保留当前高细节草，但主要集中在围栏脚、道路边、物件接触区和局部杂草团；不再形成均匀矩形草环。

推荐默认密度包络：

- 近草约 `900–1200` 株现有高细节形态；
- 中远草约 `2000–3500` 簇，每簇约 `6–10` triangles；
- 总 vegetation 视觉密度明显扩大，但不以把现有高细节草直接拉到 `4000` 为目标。

### P0-B — 一处明确出园关系

- 在一侧围栏形成自然开口或门；
- 从开口向野外延伸一条不笔直、轻微起伏的土路；
- 路面包含两条轻车辙、局部压平草和少量裸土；
- 道路必须落在同一 terrain height authority 上，不能成为悬浮贴片。

### P0-C — 拖拉机工作角

建立一组而不是一个孤立模型：

**门 / 路 → 车辙 → 紧凑型旧式拖拉机 → 小拖斗或草垛 → 木箱、桶或工具。**

硬约束：

- 使用小型、紧凑、容易读懂的农用拖拉机比例；禁止大型现代联合收割机式尺度；
- 第一实现优先程序化 / 代码生成 low-poly geometry + vertex color，直接进入 GitHub；
- 不因拖拉机引入 glTF/PBR 框架、第二 scene graph 或外部材质系统；
- 若以后改用外部正式资产，必须单独确认来源、授权、资产入库位置和性能包络，不在 P0 首轮暗中引入。

拖拉机本体建议约 `2k–4k` triangles；工作角总静态布景建议 `6k–12k` triangles。

### P0-D — 田界、树篱和树团

- 使用不对称的树篱、灌木团、少量果树或田界打断远景；
- 不围成完整封闭背景墙；
- 20–50 m 主要承担中远景遮挡和轮廓，不堆可辨认的小道具；
- 50 m 以后的内容只承担 skyline / field boundary，不成为第二个主场景。

### P0-E — 接触关系

拖拉机轮下、草垛下、树根、围栏脚和道路边必须至少通过以下一种方式建立接触：

- 地表压痕 / 材质过渡；
- 静态暗斑；
- 草密度下降与方向变化；
- 与 `terrainHeightAt()` 同权威的几何落地。

禁止“模型看起来不错，但像摆在绿色桌布上”。

## 3. 推荐空间分层

沿现有单屏 diorama 使用既有世界载体，不扩大 gameplay world：

| 距离 | 主要内容 | 目的 |
| --- | --- | --- |
| `0–6 m` | 菜园核心、菜畦、现有交互 | 保持清楚，不继续堆布景 |
| `6–20 m` | 门、道路、拖拉机工作角、近草 | 尺度与叙事主锚点 |
| `20–50 m` | 草带、田界、树篱、果树团 | 中景遮挡和纵深 |
| `50 m+` | 低频树冠、远田、山脊轮廓 | 只构成远景，不增加交互 |

构图采用**不对称三锚点**：

1. 主锚点：门 + 道路 + 拖拉机工作角；
2. 次锚点：一组田界 / 树篱；
3. 背景锚点：远处树团或草垛轮廓。

任何相机方位都应至少读到一个空间关系，但不得让外围布景四面平均围住菜园。

## 4. 渲染与所有权

### 4.1 地表

优先在现有 terrain / hardscape 世界材质中加入少量**大尺度、连续世界坐标**分区；避免继续叠高频随机噪声。

允许的变化：

- meadow / packed-earth 比例；
- road / wheel-rut mask；
- dry grass / trampled grass 大尺度带状变化；
- 与床、路、物件接触相关的局部过渡。

### 4.2 中远草

建议独立一套简化 geometry + instanced draw，但复用：

- 同一个 `Gpu` / frame owner；
- 同一 `viewProjection`、sun、fog、weather、wind；
- 现有 quality profile。

中远草应随 `full / reduced / minimum` 同步降密度，不能成为 governor 之外的永久额外负载。

### 4.3 静态布景

优先顺序：

1. 若材质与几何分支仍清楚，可扩展现有 static hardscape geometry/material kinds，保持 draw 数不增；
2. 若拖拉机/树木已经让 hardscape shader 变成复杂分支垃圾场，允许拆一个 `static-scenery` draw；
3. 不为省一个 draw 牺牲明确所有权，也不为“资产框架”预建通用 scene graph。

## 5. P0 性能预算

当前审计基线：WebGPU 主路径约 `3 passes / 8 draw calls`，默认 `1500` vegetation ceiling、DPR `1.5`。当前 runtime 的 `frameMs` 是 CPU 编码/提交时间，`frameP95Ms` 是 rAF cadence；**满帧率不等于已知 GPU 余量**。

P0 预算：

- **pass：** 必须保持 `3`；
- **draw：** 目标 `<=9`，硬上限 `10`；若使用第 10 个 draw，必须证明它比 shader/ownership 强耦合更合理；
- **新增静态 triangles：** 建议 `6k–12k`；
- **新增中远草 triangles：** 建议约 `20k–35k`；
- **透明大面积 fill：** `0`；
- **新增全屏 pass / shadow map / post-process：** `0`；
- **运行时纹理依赖：** 首轮 `0` 为目标。

性能验收不使用“看起来还是 60 FPS”作为唯一证据。固定种子、viewport、DPR、camera pose 和 quality tier，对比 P0 前后：

- `frameP95Ms`；
- draw / pass / instances / resources；
- governor 是否出现持续降档；
- desktop 与 portrait mobile 的低角度最差视图。

在基准设备上，P0 不应让原本稳定 `full` 的场景持续进入 `reduced`；若基线本身接近刷新周期，则以**前后 p95 增量**而不是绝对 FPS 判断。

## 6. 质量降级规则

沿现有 budget class 语义执行：

- `core`：菜畦、作物、土地，不降级；
- `structure`：道路、拖拉机、树篱主轮廓，保留；
- `dressing`：中远草、次要树叶、小道具，优先降密度；
- `ephemeral`：P0 不进入。

P0 若需要扩展 governor，只扩展真实消费者；不预建通用 LOD 系统。

## 7. 验收标准

- **A1** — 围栏外不再读成均匀草环，低角度可见近草、中远草、地表三层关系。
- **A2** — 至少一处门/开口、道路和车辙构成明确的空间方向。
- **A3** — 拖拉机与工作角建立可信尺度，轮胎和地面有接触关系，不漂浮。
- **A4** — 至少一组树篱/田界和一组树团打断远景，但菜园仍是第一视觉中心。
- **A5** — 四个主要相机方位中，没有一侧退化为大面积空地或整齐背景墙。
- **A6** — pass 保持 3；draw 满足预算；固定基准下无持续 governor 降档回归。
- **A7** — Canvas fallback 继续完整可玩；P0 不改变游戏状态、存档语义或点击规则。

## 8. 必须留证据

激活施工后，最终证据至少包含：

- before / after desktop 固定相机；
- desktop 低角度最近视图；
- portrait mobile 低角度视图；
- 至少四个 camera azimuth 的构图检查；
- `full` 质量档固定窗口的 metrics 对比；
- Canvas fallback smoke；
- 对道路、拖拉机、草层所有权的代码路径说明。

## 9. Non-goals

P0 不做：

- 水塘或复杂水面；
- 鸟、飞叶、风滚草等短暂动态物；
- 真实车辆物理；
- NPC、自由移动、可驾驶拖拉机；
- 大型 PBR / glTF 资产管线；
- 阴影贴图、SSR、反射重绘、后处理栈；
- 为“野外”扩大游戏地图或新增第二场景。

## 10. 停止条件

当 A1–A7 满足且性能证据没有暴露结构性问题时，P0 停止。不要在同一阶段顺手加入水塘、昆虫或粒子；这些属于后续独立阶段。
